# iptv 订阅刷新 · 操作说明

面向接手人的交接文档。三个脚本：`tools/local_speedtest.py`、`tools/merge_tv.py`、`tools/push_file.py`，
加一个把主链串起来的批处理 `refresh.bat`。

---

## 一、先回答：流程是否自动衔接

**不完全自动。** 主链（合并 → 推送）已由 `refresh.bat` 串成一键；但**测速环节无法全自动**，原因是跨设备。

三个脚本的输入输出并不是一条直线：

```
                 ┌─ 电视/盒子（另一台设备，人工搬运）─────────────┐
                 │  handoff/speedtest.py  →  tv_result.txt        │
                 └───────────────────┬───────────────────────────┘
                                     ↓  拷到 output/tv_result.txt
[PC] local_speedtest.py ──┬─→ output/local_result.txt    ┌──────────┴──────────┐
     （本机移动家宽测速）  └─→ output/rates.tsv  ────────→│  merge_tv.py        │
                                                          │  底表+网关+黑名单   │
                             config/extra_hubei.txt ─────→│  + 速率过滤         │
                             config/url_blacklist.txt ──→└──────────┬──────────┘
                                                                     ↓
                                                          output/curated.txt
                                                                     ↓
                                                          push_file.py → GitHub
```

三个不衔接的点，必须知道：

| 现象 | 原因 |
|---|---|
| `local_speedtest.py` 的产物**不能**直接喂给 `merge_tv.py` 当底表 | merge 的底表是 `tv_result.txt`（**电视端**实测），不是 PC 端结果。两者是两次独立测量，不是上下游 |
| `local_speedtest.py` 默认 `--out` 就是 `output/curated.txt` | 直接串联会覆盖 merge 的产物。批处理里显式加了 `--out output/local_result.txt` 规避 |
| 测速必须在电视/盒子上跑一次 | 盒子与 PC 可能不同网段/不同解码能力，云端或 PC 的结果都不能替代 |

所以 `rates.tsv` 是 PC 测速唯一进入主链的通道——**它只作过滤依据，不作底表**。

---

## 二、三个脚本各自干什么

### 1. `local_speedtest.py` —— 本机测速

从订阅源现场建池或读云端候选池，逐条解析 HLS 到 `.ts` 分片实测速率。

```bash
# 常用：从 12 个订阅源现场建池，全量测速（约 5 分钟）
python tools/local_speedtest.py --from-subscribe --extra config/extra_hubei.txt --seconds 3

# 只测央视，快速验证
python tools/local_speedtest.py --from-subscribe --only CCTV --seconds 3

# 试跑 40 条确认环境
python tools/local_speedtest.py --from-subscribe --limit 40
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--from-subscribe` | 关 | 从 `config/subscribe.txt` 现场抓源建池；不加则读云端 `user_result.txt` |
| `--extra` | 无 | 追加 `name,url` 源文件，如 `config/extra_hubei.txt` |
| `--seconds` | 3 | 每片采样秒数。**别低于 3**，2 秒会把启动慢的源误判为 0 |
| `--min-mbps` | 1.5 | 及格线 |
| `--per-channel` | 5 | 每台最多留几条 |
| `--strict-group` | 卫视 | 该组不保底：全台低于门槛就整台丢弃。可多次 |
| `--out` | `output/curated.txt` | 结果路径。**批处理里会改到 `local_result.txt`** |
| `--rates` | `output/rates.tsv` | 速率索引，供 merge 过滤 |

产出：`local_result.txt`（或 `--out` 指定）+ `rates.tsv`（`台名 \t Mbps \t URL`）。

### 2. `merge_tv.py` —— 合并成最终订阅

以电视端实测为底表，把湖北网关源插到对应台第一条，套黑名单与速率过滤。

```bash
python tools/merge_tv.py --drop-group 凤凰频道 --drop-group 广东频道 --move 广州综合=卫视频道
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--tv` | `output/tv_result.txt` | 电视端底表，**顺序即该网络的速率降序** |
| `--gw` | `config/extra_hubei.txt` | 网关源，插到对应台第一条 |
| `--rates` | `output/rates.tsv` | 速率表；缺失则跳过过滤（会打印警告） |
| `--min-mbps` | 2.0 | 严格组门槛，低于此值的线路丢弃 |
| `--strict-group` | 卫视 | 启用过滤的分组关键字，可多次 |
| `--no-filter` | 关 | 关闭速率过滤，全量输出 |
| `--per-channel` | 6 | 每台最多几条 |
| `--drop-group` | 无 | 整组丢弃，可多次 |
| `--move` | 无 | `台名=目标组`，可多次 |

固定要带的三件事（`refresh.bat` 已内置）：
`--drop-group 凤凰频道 --drop-group 广东频道 --move 广州综合=卫视频道`

**过滤规则**（本次新增）：
- 只对 `--strict-group` 命中的组生效，默认「卫视」。
- 线路有速率记录且 `< --min-mbps` → 丢弃。
- 某台所有线路都被丢弃 → **整台从输出中消失**，日志里列出丢弃清单与速率。
- 央视不参与（有网关兜底，且地方速率低不等于不可播）。
- **没有速率记录的线路不误杀**，一律保留。

### 3. `push_file.py` —— 单文件推送

走 GitHub Contents API，不 clone 仓库。

```bash
python tools/push_file.py output/curated.txt --message "curated: 刷新"
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `path` | 必填 | 相对项目根的路径 |
| `--repo` | `lanternook/iptv` | 目标仓库 |
| `--branch` | `main` | 分支 |
| `--message` | 自动 | 提交信息 |

依赖 `tools/token.txt`（GitHub PAT，需 Contents 读写）。该文件已在 `.gitignore` 里。

## 三、批处理 `refresh.bat`

双击或命令行运行，解决两件事：**参数不会记错**、**编码不会乱码**。

| 命令 | 行为 | 耗时 |
|---|---|---|
| `refresh.bat` | 合并 → 推送（日常用这个） | 约 5 秒 |
| `refresh.bat dry` | 只合并，生成 `curated.txt` 不上传 | 约 3 秒 |
| `refresh.bat test` | 先跑 PC 全量测速生成 `rates.tsv`，再合并 → 推送 | 约 6 分钟 |

`test` 模式的测速结果写到 `output/local_result.txt`，**不会覆盖** `curated.txt`。

失败会在对应步骤停下并给出原因：缺 python、缺 `token.txt`、缺 `tv_result.txt`、测速无产出、合并报错、推送失败。

### 关于编码（乱码修复说明）

两个 bat 都是 **GBK 编码 + CRLF 换行 + 无 BOM**。

原先 `handoff/run.bat` 是 UTF-8 无 BOM 配 `chcp 65001`，中文显示为乱码。根因：**cmd 按系统代码页（936/GBK）逐行解析 bat 文本**，UTF-8 字节在这一步就被错误解码；`chcp 65001` 只改变之后的**输出**代码页，救不了已经解析错的字符串。

所以规则是二选一，不能混：

- 文件 GBK 编码 → 保持系统代码页 936，**不要**写 `chcp 65001`
- 文件 UTF-8 → 必须带 BOM 且 `chcp 65001`（老系统兼容性差）

本项目统一选第一种。**改这两个 bat 时，编辑器必须存成 GBK（ANSI）**，否则乱码复现。

## 四、完整操作流程

### 日常（源没变，只想重排或重推）

```bat
refresh.bat
```

### 定期重测（建议每 2~4 周，或发现某台开始卡）

1. 电视/盒子上跑交接包：把 `dist/iptv_speedtest_handoff_*.zip` 拷过去解压，双击 `run.bat`，
   结果 `output/result_*.txt` 拷回 `E:\workbuddy\iptv\output\tv_result.txt`（覆盖）
2. PC 上：`refresh.bat test`
3. 等 5 分钟，`python tools/verify_feed.py` 核对镜像内容
4. 播放器里刷新订阅

### 只调频道/网关映射

```bash
# 改 config/user_demo.txt（频道）或 config/extra_hubei.txt（网关编号）
python tools/merge_tv.py --drop-group 凤凰频道 --drop-group 广东频道 --move 广州综合=卫视频道
python tools/push_file.py output/curated.txt --message "curated: 调整映射"
```

## 五、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 合并后卫视少了很多台 | 速率过滤生效 | 看日志「丢弃台（低于 2.0 Mbps）」；要放宽用 `--min-mbps 1.0` |
| 合并提示「未找到速率表」 | 没跑过 PC 测速 | 跑 `refresh.bat test`，或先接受不过滤 |
| 某台整台消失但速率不低 | 该台所有线路都被 `url_blacklist.txt` 命中 | 查 `config/url_blacklist.txt` 关键字 |
| 推送成功但播放器看到旧内容 | 镜像 CDN 缓存约 5 分钟 | 等 5 分钟，或改用 ghfast |
| 推送 403 | PAT 缺 Contents 写权限 | 重新签发，只勾 `repo` |
| bat 中文乱码 | 文件被存成 UTF-8 | 另存为 GBK/ANSI |
| 测速结果大量 0 Mbps | 走了代理或带宽被占 | 关代理直连；测速时别播视频 |

## 六、硬规则（违反会出错）

1. 测速必须在本机直连做，云端（海外 runner）结果对国内无参考价值。
2. HLS 测速要解析到 `.ts` 分片，采样 3 秒；`.m3u8` 本身是文本，测不出速率。
3. 推送后镜像有约 5 分钟缓存，核对内容要比起 md5，不能只看 HTTP 200。
4. 网关编号 ≠ 台号：`N≤5` 直接用，`N=6` 是 CCTV-5+，`N≥7` 取 `N-1`，CCTV-17 用 18。
5. 合并时 `--drop-group`/`--move` 必须显式带上，否则凤凰与广东组会回流。
