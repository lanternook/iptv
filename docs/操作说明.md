# iptv 订阅 · 操作说明

## 一句话

双击 `update.bat`（或 `python tools/pipeline.py`），自动跑完：体检现有线路 → 换掉失效 → 补源 → 推送 → 校验。

**前提**：本机与电视在同一网络，且不走代理（测速必须直连）。

---

## 一、脚本职责

| 脚本 | 干什么 | 产出 |
|---|---|---|
| `tools/pipeline.py` | 总调度。依次调用下面三个，任一步失败就停并保护旧订阅 | `output/curated.txt` |
| `tools/local_speedtest.py` | 抓订阅源建池 + 逐条测 HLS 真实速率 | `output/measured.txt`（底表）、`output/rates.tsv`（速率索引） |
| `tools/merge_tv.py` | 合并：网关源置首、URL 黑名单、卫视低速率过滤、央视自然排序 | `output/curated.txt` |
| `tools/reorder_gateways.py` | 按**目标机所在网络**实测优先级重排央视的网关线路（三网关自动补齐、编号随网关走） | 原地改 `output/curated.txt` |
| `tools/push_file.py` | 用 Contents API 推送文件到 GitHub（免 clone） | 远端仓库 |
| `update.bat` | **主入口**，双击即跑（GBK 编码，勿改存 UTF-8） | — |
| `refresh.bat` | 历史入口名，内部直接转调 `update.bat`，**两者功能完全一致**，参数也一样 | — |

**数据流向**：订阅源 → 测速底表 → 合并 → `curated.txt` → GitHub → 播放器订阅地址。

---

## 二、日常操作

### 全量刷新（最常用）

```
双击 update.bat
```

约 5~10 分钟。跑完播放器刷新订阅即可。

### 常用变体

```bat
update.bat --dry                          :: 只预览，不写文件不推送
update.bat --no-push                      :: 生成但不上传
update.bat --apply output\measured.txt    :: 用测速机结果换血（10 秒）
update.bat --rebuild                      :: 全量重建：联网抓源池 + 全量测速（5~10 分钟）
update.bat --rebuild --from-pool          :: 用本地 output\pool.txt 全量测速，不联网
update.bat --seconds 5                    :: 采样 5 秒（默认 3 秒）
```

### 只改配置不改源

改完 `config/` 里的文件后：

```bash
python tools/merge_tv.py --tv output/measured.txt --drop-group 凤凰频道 --drop-group 广东频道 --move 广州综合=卫视频道
python tools/push_file.py
```

## 三、配置放哪

| 文件 | 作用 |
|---|---|
| `config/publish.json` | **推送配置集中在这里**：仓库、分支、token 路径、要推哪些文件、镜像列表 |
| `config/user_demo.txt` | 频道模板（要哪些台）。加台/删台改这里 |
| `config/subscribe.txt` | 主订阅源（12 个，日常维护） |
| `config/subscribe_pool.txt` | 外部聚合池（量大但杂，自动按模板过滤） |
| `config/extra_hubei.txt` | 湖北移动网关编号 → 台名映射（人工维护，失效需手工改） |
| `config/extra_gateway2.txt` | 219.147.245.238:25480 的编号映射（**顺移**，CCTV-17 在 17） |
| `config/gateway_pool.txt` | 网关池：`host:port 中位Mbps 编号方案 覆盖说明`（测速口径必须与目标机同网） |
| `config/url_blacklist.txt` | URL 关键字黑名单，命中即丢 |
| `tools/token.txt` | GitHub PAT（已 gitignore，不入库） |

## 四、出问题怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示「达标线路仅 N 条，判定为网络异常」 | 测速结果太少，多半是网络/代理问题 | 关掉代理重跑；确认没在看视频；先用 `--dry` 看体检结果 |
| 提示「缺少 tools/token.txt」 | PAT 文件没了 | 把 GitHub PAT 写进该文件（只勾 `repo`） |
| 提示「未找到速率表」 | 没跑测速直接合并 | 跑全量，或加 `--no-filter` 跳过过滤 |
| 某台整台消失 | 该台所有线路测速低于 2.0 Mbps | 正常行为；要放宽用 `--min-mbps 1.0` |
| 央视的湖北网关源被换成了咪咕/voc 等 | 旧版换血对央视也生效，网关并发测被误判 | 已修：换血默认只动卫视；恢复用备份或重跑 `--all-groups` 前先 `--dry` 预览 |
| 央视某台串台 | 网关编号变了 | 抽帧确认：`python tools/grab_frames.py http://120.40.39.246:352 10,11 tmp/frames`，改 `config/extra_hubei.txt` |
| 本机是电信，但目标机是移动 | 跨网测出的排名不可用（会反向） | 用同网手机测：`adb push tools/phone_speed.sh /data/local/tmp/` → `adb shell "sh /data/local/tmp/phone_speed.sh /data/local/tmp/urls.txt"`，每行 `台名\|url`；查覆盖用 `phone_cov.sh` |
| 网关某号 404 | 网关换号 | `python tools/enum_hls.py --tpl "http://120.40.39.246:352/newlive/live/hls/{n}/live.m3u8" --from 1 --to 40` |
| 推送成功但播放器还是旧的 | 镜像 CDN 缓存约 5 分钟 | 等 5 分钟；或换 ghfast 那条地址 |
| 推送 403 | PAT 无 Contents 写权限 | 重新签发，只勾 `repo` |
| 批处理中文乱码 | 被编辑器存成 UTF-8 | 另存为 GBK/ANSI（不能带 BOM，不能加 chcp 65001） |
| 某个订阅源 ERR | 源仓库改名/删除 | 从 `config/subscribe*.txt` 删掉那行即可，不影响其它 |
| 日志文件乱码 | 旧版按 UTF-8 解码 GBK 子进程输出 | 已修（按系统代码页解码）；日志在 `output/logs/run_*.log`，UTF-8 编码，用 VS Code 或记事本打开正常 |
| 找不到日志 | 日志按运行时间命名 | `output/logs/` 下取最新的 `run_YYYYmmdd_HHMMSS.log` |

**保护机制**：
- 合并后条数低于 20 时不推送，旧订阅保持原样——不会因为一次网络抖动把订阅推坏。
- **换血默认只动「卫视」组**。央视（湖北网关源）整组保留，因为网关是单 IP 转发服务，并发测速会被限流误判成死链。要动央视得显式加 `--all-groups`。

## 六、网关编号（不同网关不一样，串台先查这里）

路径模板都是 `/newlive/live/hls/{N}/live.m3u8`，但 **N 的含义随网关不同**，抓帧逐个核实过：

| 网关 | 编号方案 | CCTV-5+ | CCTV-6~15 | CCTV-17 |
|---|---|---|---|---|
| `118.122.144.115:8888` | 直编 | N=16 | N=6~15 | N=17 |
| `219.147.245.238:25480` | 顺移 | N=6 | N=7~16 | N=17 |
| `120.40.39.246:352` | 顺移 | N=6 | N=7~16 | **N=18** |

- 三台网关都**没有 CCTV-16**，CCTV-16 只有 `gmxw.7766.org` 一条。
- 改网关后必须抽帧验台：`python tools/grab_frames.py http://<host:port> 6,10,17 tmp/frames`，看图对台名。
- 优先级写在 `tools/reorder_gateways.py` 的 `PRIORITY` 里，改完直接跑它，`--dry` 先预览。

**测速口径**：排序必须用**目标机所在网络**（湖北移动）的数据。电信网络下测出的排名与移动完全相反（219.147 电信 43 Mbps / 移动 8.97），拿错数据排出来必卡。

## 七、三条硬规则

1. 测速必须直连，不能走代理，也不能边测边看视频。
2. HLS 要解析到 `.ts` 分片再计时，采样 3 秒；2 秒会把启动慢的源误判为 0。
3. 推送后镜像有约 5 分钟缓存，核对内容要比字节数或 md5，不能只看 HTTP 200。
