# iptv 订阅 · 操作说明

## 一句话

双击 `update.bat`（或 `python tools/pipeline.py`），自动跑完：体检现有线路 → 换掉失效 → 补源 → 推送 → 校验。

**前提**：本机与电视在同一网络，且不走代理（测速必须直连）。

---

## 一、脚本职责

| 脚本 | 干什么 | 产出 |
|---|---|---|
| `tools/pipeline.py` | 总调度。依次调用下面三个，任一步失败就停并保护旧订阅 | `output/curated.txt` |
| `tools/local_speedtest.py` | 抓订阅源建池 + 逐条测 HLS 真实速率 | `output/measured.txt`（底表）、`output/rates.tsv`（速率索引） |
| `tools/merge_tv.py` | 合并：网关源置首、URL 黑名单、卫视低速率过滤、央视自然排序 | `output/curated.txt` |
| `tools/reorder_gateways.py` | 按**目标机所在网络**实测优先级重排央视的网关线路（三网关自动补齐、编号随网关走） | 原地改 `output/curated.txt` |
| `tools/push_file.py` | 用 Contents API 推送文件到 GitHub（免 clone） | 远端仓库 |
| `tools/find_gateway.py` | **找源主入口**：GitHub 代码搜索发现同结构网关 → 串行验证 → 按速率写池 | `config/gateway_pool.txt`、`output/phone_urls.txt` |
| `tools/find_source.py` | 找源**备选**：抓零散直链 m3u8（网关都挂了才用） | `output/found_url.txt` |
| `tools/phone_speed.sh` | 跑在手机上（目标机同网）测 HLS 速率，串行避免网关限流 | 每行 `标签\|Mbps\|code\|bytes` |
| `tools/apply_phone_speed.py` | 用手机测速结果给指定分组的线路排序（死链沉底不删） | 原地改 `output/curated.txt` |
| `tools/grab_frames.py` | 抽帧识台，用来确认网关的编号方案 | `tmp/frames/*.png` |
| `find_gateway.bat` | 双击找源（GBK，勿存 UTF-8） | — |
| `phone_speed.bat` | 双击跑「手机测速 → 回灌网关池」全流程 | — |
| `update.bat` | **主入口**，双击即跑（GBK 编码，勿改存 UTF-8） | — |
| `refresh.bat` | 历史入口名，内部直接转调 `update.bat`，**两者功能完全一致**，参数也一样 | — |

**数据流向**：订阅源 → 测速底表 → 合并 → `curated.txt` → GitHub → 播放器订阅地址。

## 二、日常操作

### 全量刷新（最常用）

```
双击 update.bat
```

约 5~10 分钟。跑完播放器刷新订阅即可。

### 常用变体

```bat
update.bat --dry                          :: 只预览，不写文件不推送
update.bat --no-push                      :: 生成但不上传
update.bat --apply output\measured.txt    :: 用测速机结果换血（10 秒）
update.bat --rebuild                      :: 全量重建：联网抓源池 + 全量测速（5~10 分钟）
update.bat --rebuild --from-pool          :: 用本地 output\pool.txt 全量测速，不联网
update.bat --seconds 5                    :: 采样 5 秒（默认 3 秒）
```

### 只改配置不改源

改完 `config/` 里的文件后：

```bash
python tools/merge_tv.py --tv output/measured.txt --drop-group 凤凰频道 --drop-group 广东频道 --move 广州综合=卫视频道
python tools/push_file.py
```

## 三、配置放哪

| 文件 | 作用 |
|---|---|
| `config/publish.json` | **推送配置集中在这里**：仓库、分支、token 路径、要推哪些文件、镜像列表 |
| `config/user_demo.txt` | 频道模板（要哪些台）。加台/删台改这里 |
| `config/subscribe.txt` | 主订阅源（12 个，日常维护） |
| `config/subscribe_pool.txt` | 外部聚合池（量大但杂，自动按模板过滤） |
| `config/extra_hubei.txt` | 湖北移动网关编号 → 台名映射（人工维护，失效需手工改） |
| `config/extra_gateway2.txt` | 219.147.245.238:25480 的编号映射（**顺移**，CCTV-17 在 17） |
| `config/gateway_pool.txt` | 网关池：`host:port 中位Mbps 编号方案 覆盖说明`（测速口径必须与目标机同网） |
| `config/url_blacklist.txt` | URL 关键字黑名单，命中即丢 |
| `tools/token.txt` | GitHub PAT（已 gitignore，不入库） |

## 四、出问题怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示「达标线路仅 N 条，判定为网络异常」 | 测速结果太少，多半是网络/代理问题 | 关掉代理重跑；确认没在看视频；先用 `--dry` 看体检结果 |
| 提示「缺少 tools/token.txt」 | PAT 文件没了 | 把 GitHub PAT 写进该文件（只勾 `repo`） |
| 提示「未找到速率表」 | 没跑测速直接合并 | 跑全量，或加 `--no-filter` 跳过过滤 |
| 某台整台消失 | 该台所有线路测速低于 2.0 Mbps | 正常行为；要放宽用 `--min-mbps 1.0` |
| 央视的湖北网关源被换成了咪咕/voc 等 | 旧版换血对央视也生效，网关并发测被误判 | 已修：换血默认只动卫视；恢复用备份或重跑 `--all-groups` 前先 `--dry` 预览 |
| 央视某台串台 | 网关编号变了 | 抽帧确认：`python tools/grab_frames.py http://120.40.39.246:352 10,11 tmp/frames`，改 `config/extra_hubei.txt` |
| 本机是电信，但目标机是移动 | 跨网测出的排名不可用（会反向） | 用同网手机测：`adb push tools/phone_speed.sh /data/local/tmp/` → `adb shell "sh /data/local/tmp/phone_speed.sh /data/local/tmp/urls.txt"`，每行 `台名\|url`；查覆盖用 `phone_cov.sh` |
| 网关某号 404 | 网关换号 | `python tools/enum_hls.py --tpl "http://120.40.39.246:352/newlive/live/hls/{n}/live.m3u8" --from 1 --to 40` |
| 推送成功但播放器还是旧的 | 镜像 CDN 缓存约 5 分钟 | 等 5 分钟；或换 ghfast 那条地址 |
| 推送 403 | PAT 无 Contents 写权限 | 重新签发，只勾 `repo` |
| 批处理中文乱码 | 被编辑器存成 UTF-8 | 另存为 GBK/ANSI（不能带 BOM，不能加 chcp 65001） |
| 某个订阅源 ERR | 源仓库改名/删除 | 从 `config/subscribe*.txt` 删掉那行即可，不影响其它 |
| 日志文件乱码 | 旧版按 UTF-8 解码 GBK 子进程输出 | 已修（按系统代码页解码）；日志在 `output/logs/run_*.log`，UTF-8 编码，用 VS Code 或记事本打开正常 |
| 找不到日志 | 日志按运行时间命名 | `output/logs/` 下取最新的 `run_YYYYmmdd_HHMMSS.log` |

**保护机制**：
- 合并后条数低于 20 时不推送，旧订阅保持原样——不会因为一次网络抖动把订阅推坏。
- **换血默认只动「卫视」组**。央视（湖北网关源）整组保留，因为网关是单 IP 转发服务，并发测速会被限流误判成死链。要动央视得显式加 `--all-groups`。

## 六、网关编号（不同网关不一样，串台先查这里）

路径模板都是 `/newlive/live/hls/{N}/live.m3u8`，但 **N 的含义随网关不同**，抓帧逐个核实过：

| 网关 | 编号方案 | CCTV-5+ | CCTV-6~15 | CCTV-17 |
|---|---|---|---|---|
| `118.122.144.115:8888` | 直编 | N=16 | N=6~15 | N=17 |
| `219.147.245.238:25480` | 顺移 | N=6 | N=7~16 | N=17 |
| `120.40.39.246:352` | 顺移 | N=6 | N=7~16 | **N=18** |

- 三台网关都**没有 CCTV-16**，CCTV-16 只有 `gmxw.7766.org` 一条。
- 改网关后必须抽帧验台：`python tools/grab_frames.py http://<host:port> 6,10,17 tmp/frames`，看图对台名。
- 优先级写在 `tools/reorder_gateways.py` 的 `PRIORITY` 里，改完直接跑它，`--dry` 先预览。

**测速口径**：排序必须用**目标机所在网络**（湖北移动）的数据。电信网络下测出的排名与移动完全相反（219.147 电信 43 Mbps / 移动 8.97），拿错数据排出来必卡。

## 七、找源（网关挂了 / 要加备选）

**优先级：网关 > 直链。** 一个 `IP:port/newlive/live/hls/{N}/live.m3u8` 覆盖 17 个央视台，编号统一、速率稳定；零散直链只能一两条台，还经常带过期 token。所以先找网关，直链只作兜底。

### 方法（四步）

**第 1 步：发现网关** —— `find_gateway.bat` 或 `python tools/find_gateway.py`

原理：同结构网关散落在社区的 txt/m3u 里，用 GitHub 代码搜索按路径特征捞出来。
搜索关键词默认两个：`newlive/live/hls`、`newlive/live/hls/1/live.m3u8`。

跑起来会打 5 步进度，每步都带耗时：

```
[  0.1s] 已有网关 8 个（gateway_pool.txt）
[  0.1s] [1/5] GitHub 代码搜索
[  3.2s]   1/2 关键词「newlive/live/hls」命中文件 30
[  6.1s]   2/2 关键词「newlive/live/hls/1/live.m3u8」命中文件 30
[  6.1s] [2/5] 去重后 52 个文件，逐个拉内容提取
[  9.4s]   1/52 kimwang1978/collect-txt            +4 个网关
...
[ 52.7s]   提取完成：33 个不同 host:port
[ 52.7s] [3/5] 去掉池里已有的 8 个，剩 25 个新候选
[ 52.7s] [4/5] 串行验证（每个约 3~10 秒，共 25 个）
[ 55.1s]   1/25 113.57.140.161:10081      OK 1.50 Mbps
[ 58.3s]   2/25 118.122.144.115:8888      OK 17.77 Mbps
...
[240.0s] [5/5] 可用 8 个，已写入 config/gateway_pool.txt
```

常用参数：

```bat
find_gateway.bat                    :: 默认：搜索 2 页 + 验证 + 写池
find_gateway.bat --pages 3          :: 多翻页，候选更多
find_gateway.bat --verify-only      :: 不搜索，只复验池里已有的（约 3 分钟）
find_gateway.bat --all              :: 不跳过池里已有的
find_gateway.bat --phone            :: 只生成手机测速清单，不在本机测
```

**第 2 步：用目标机同网的精测速率排序** —— `phone_speed.bat`

本机（电信）测出来的速率只能判活，**排序必须用目标机所在网络（湖北移动）**。
两个网络下排名会完全反过来（同一网关：电信 43 Mbps / 移动 8.97 Mbps）。

```bat
phone_speed.bat
```

它做四件事：`--phone` 生成清单 → push 到手机 → 手机串行测速 → `--ingest` 回灌写池。
手机上跑的是 `tools/phone_speed.sh`，参数 2 是采样秒数（默认 4，批量用 3）。

手动版：

```bash
python tools/find_gateway.py --phone
adb push tools/phone_speed.sh /data/local/tmp/
adb push output/phone_urls.txt /data/local/tmp/urls.txt
adb shell "sh /data/local/tmp/phone_speed.sh /data/local/tmp/urls.txt 3" > output/phone_result.txt
python tools/find_gateway.py --ingest output/phone_result.txt
```

**第 3 步：抓帧确认编号方案** —— 必做，否则会串台

```bash
python tools/grab_frames.py http://<新网关:端口> 1,6,10,17 tmp/frames
```

看图确认：`hls/6` 是 CCTV-5+ 还是 CCTV-6？`hls/10` 是 CCTV-9 还是 CCTV-10？`hls/17` 是 CCTV-17 还是空？
确认后在 `tools/reorder_gateways.py` 的 `PRIORITY` 里登记（host + 编号方案表），再跑：

```bash
python tools/reorder_gateways.py --dry     # 先预览
python tools/reorder_gateways.py           # 落盘
python tools/push_file.py output/curated.txt
```

**第 4 步（备选）：直链源兜底** —— `python tools/find_source.py`

网关全挂时才用。它搜 4 个关键词、提取所有 m3u8 直链、本机粗筛判活，产出 `output/phone_urls.txt` 供手机精测，回灌后写 `output/found_url.txt`。

```bash
python tools/find_source.py --pages 1 --limit 40
python tools/find_source.py --ingest output/phone_result.txt
```

### 踩坑清单

| 坑 | 表现 | 对策 |
|---|---|---|
| 并发测网关 | 8 条一起测全部 0.00 Mbps | 网关是单 IP 转发，**必须串行**；两个测速脚本都是串行 |
| 用错网络的速率排序 | 排出来的首选台反而最卡 | 本机电信 ≠ 目标机移动，一律用手机测 |
| 编号照抄旧网关 | 串台（CCTV-3 放出来是别的台） | 每个新网关都抓帧验台，编号方案见表 |
| 采样太短 | 启动慢的源被判 0 | 采样 ≥3 秒，HLS 要解析到 `.ts` 分片再计时 |
| 搜到 0 个候选 | 第 1 步就没命中 | 代理没开 / token 失效；`gh_api.py` 会自动在直连和 `127.0.0.1:7897` 间切换 |
| 改完播放器没变 | 拉到的还是旧文件 | `push_file.py` 现在每次推送后自动 purge jsDelivr 缓存；仍不生效就换节点（见下） |

### 订阅地址用哪个节点

同一份文件在 jsDelivr 各节点缓存时长不同，实测（2026-10-31，湖北移动）：

| 节点 | 移动网络可访问 | 缓存刷新 |
|---|---|---|
| `gcore.jsdelivr.net` | ✅ 正常（约 1.4s） | 快，purge 后立即生效 |
| `testingcf.jsdelivr.net` | ✅ 正常（约 1.3s） | 快 |
| `fastly.jsdelivr.net` | ✅ 正常（约 0.7s） | **慢，purge 后仍可能发旧版** |
| `cdn.jsdelivr.net` | ❌ 不通（HTTP 000） | — |

**结论：订阅地址用 `https://gcore.jsdelivr.net/gh/lanternook/iptv@main/output/curated.txt`。**
手机上「我的电视直播版」的源已经改成这个；电视盒子同样要改。

手动清缓存（推送脚本会自动做，这里是兜底）：

```bash
curl "https://purge.jsdelivr.net/gh/lanternook/iptv@main/output/curated.txt"
```

## 八、三条硬规则

1. 测速必须直连，不能走代理，也不能边测边看视频。
2. HLS 要解析到 `.ts` 分片再计时，采样 3 秒；2 秒会把启动慢的源误判为 0。
3. 推送后镜像有约 5 分钟缓存，核对内容要比字节数或 md5，不能只看 HTTP 200。
